Frequently Asked Questions

Find quick answers to common questions about uploading datasets, quality analysis, controlled data cleaning, and security.

1. File Uploads & Requirements

What file formats and sizes are supported?
The application supports CSV (Comma-Separated Values) files up to 16 MB. It automatically senses various common delimiters including commas (,), semicolons (;), tabs (\t), and pipes (|), with multi-encoding support (UTF-8, UTF-8 with BOM, Latin-1, CP1252).
Why did my upload fail or get rejected?
Common reasons for upload rejection include:
  • The file has an unsupported extension (only .csv files are accepted).
  • The file is empty (0 bytes).
  • The file exceeds the 16 MB limit.
  • The CSV contains severely corrupted or unparseable lines.
  • You hit the rate limit (more than 40 uploads within 10 minutes from the same IP).

2. Data Quality Checks & Analysis

How are missing values detected?
Missing value detection accounts for empty cells, whitespace-only entries, nulls, and standard missing value tokens (such as NA, N/A, nan, NaN, null, None, ?, and -). You can see exact counts, percentages per column, and sample row numbers.
What rule is used for duplicate detection?
By default, duplicate detection checks for exact row duplicates where every column in a row matches an earlier row. The first instance of the record is preserved, and all subsequent matching rows are identified for review.
What are column data type inconsistencies?
The analyzer infers the intended semantic type of each column (Integer, Decimal, Datetime, Boolean, or Text). If a numeric column contains text values (such as "unknown" or "twenty"), or a date column contains invalid date strings, they are flagged as type inconsistencies with row numbers and failure rationales.
How do validation rules work?
Validation rules check specific constraints on your columns, such as non-negative age (Age ≥ 0), strictly positive amounts (Price > 0), required (non-empty) fields, and RFC-compliant email formats. You can select which rules to evaluate in the Validation Rules tab.

3. Controlled Cleaning & Safety

Will cleaning overwrite or destroy my original file?
No, never. The application adheres strictly to non-destructive data principles. The original uploaded dataset is stored separately and remains immutable. All cleaning operations are applied to an isolated working copy. You can click Reset to Original Dataset at any time to undo all operations.
What cleaning operations can I perform?
Supported operations include:
  • Removing all duplicate rows.
  • Dropping rows containing missing values (across any column or specific columns).
  • Filling missing values with a constant value, column mean, median, or mode.
  • Converting columns to Integer, Decimal, Datetime, Boolean, or clean String.
  • Stripping leading and trailing whitespace from string columns.
  • Dropping unwanted columns.
What is CSV Formula Injection (DDE) sanitization?
When CSV files containing formula characters like =, +, -, or @ are opened in spreadsheet software like Microsoft Excel, they can execute external commands or formulas. Data Quality Checker neutralizes these risks during export by safely escaping formula-triggering characters.

4. Privacy & Data Retention

How long is my uploaded data retained?
Sessions are stored purely in temporary volatile memory and expire automatically after 2 hours of inactivity. Data is never permanently saved to public disks or shared with any third-party services.
